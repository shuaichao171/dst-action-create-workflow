# 饥荒动作制作流程

整理日期：2026-09-10。本文是可迁移的流程入口，用于把角色参考制作成可编辑、可验收、可编译并能接入《饥荒联机版》的动画资产。

先读 [00-注意事项](00-注意事项.md)，再按标准流程执行。注意事项定义边界，流程文件定义操作步骤；模板是记录工具，案例是附录，不能互相替代。

## 标准流程

```text
G0 需求与运行时契约
  -> G1 参考、风格和独立三视图
  -> G2 部件方案、父子关系、接缝和显隐
  -> P0 代表性短动作、SCML 对照、官方编译样包和隔离加载
  -> G3 全部透明 PNG、来源、锚点和完整性
  -> G4 实际 PNG 静态拼合与三视图对照
  -> G5 OpenSpine 骨骼、绑定、四方向动作、原生渲染和用户视觉审查
  -> G6 同版 SCML + PNG + 官方 Mod Tools 编译包 + 构建/校验记录
  -> G7 明确范围内的资源接入、游戏内、主机/远端和联机验证
```

### G0：需求与契约

在 06 的开工任务单填写个体、方向、动作、bank/build/entity、装备/皮肤、命中事件、FPS、交付格式、环境变量和输出目录。运行时调查在制作前完成；不明确的动作名、事件或 build 归属写“待确认”。

### G1—G2：参考、拆件和静态装配

按 01 冻结每个个体的三视图和版本。按 02 写部件清单，登记父部件、语义关节、接头、遮挡、显隐、PNG 尺寸、锚点和 SHA-256。静态拼合必须使用实际交付 PNG。

### P0：小样先跑通链路

在批量制作前，用一个代表性个体和短动作验证图片加载、骨骼继承、约束、保存重开、SCML 导出、官方 Mod Tools 编译、包结构和隔离加载。保存实际命令、工具版本、退出码、日志和样包；P0 未完成时只能交阶段预览。

### G3—G5：制作、绑定和动作

按 03 建真实骨骼和附件，逐个方向制作动作。用 07 的专项规则检查人形手臂或拳击；其他武器、四足或特殊角色按自身动作规格。原生渲染逐帧检查关键姿势、极限姿势、遮挡、换图、层级和循环，再交用户审查。

### G6：导出和编译

按 04 独立重建 SCML 画面，核对 `object_ref`、`z_index`、pivot、矩阵、时间网格和事件。使用官方 Mod Tools 编译到独立输出目录，检查 `anim.bin`、`build.bin`、`atlas-*.tex`、bank/build、动作、方向、帧数、CRC 和 SHA-256。源文件修改后不得复用旧包。

### G7：接入和实测

只有在 G6 完成并明确接入范围后才更新模组资源或代码。按 04 的用例测试实际尺寸、方向、状态衔接、攻击/死亡、装备、骑乘、打断、重载、主机和远端客户端。没有运行游戏时，在记录中明确写“未游戏验证”。

## 阶段门槛

| 阶段 | 必须交付 | 放行条件 |
|---|---|---|
| G0 | 需求、动作表、运行时契约 | 范围、未知项和验证边界已记录 |
| G1 | 参考、候选风格、独立三视图 | 用户确认基准版本 |
| G2 | 部件方案、父子关系、显隐和命名 | 能覆盖预定姿势和动作 |
| P0 | 小样源、SCML、编译样包、隔离加载记录 | 代表性链路实际跑通 |
| G3 | 全部 PNG、来源、锚点和完整性报告 | 无漏件、残底和断边 |
| G4 | 静态拼合和对照 | 比例、颜色、层级和连接可接受 |
| G5 | 可编辑骨架、四向动作、逐帧预览 | 专项回归完成并交用户审查 |
| G6 | 同版源文件、编译包、日志和哈希 | 官方编译、包结构和画面对照完成 |
| G7 | 接入和游戏测试记录 | 主机、远端和联机结果符合范围 |

## 路径和发布约定

流程仓库只发布 Markdown、示例模板和必要的 `.gitattributes`；不发布 OpenSpine、官方 Mod Tools、游戏安装、个人配置、案例大素材或本机缓存。项目使用相对路径，工具路径通过 `DST_GAME_HOME`、`OPENSPINE_HOME`、`DST_MOD_TOOLS_HOME`、`DST_SCML_ANALYZER` 或未提交的本地配置提供。对外打包流程目录时排除 `.git/`。
